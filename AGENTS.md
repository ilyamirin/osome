# AGENTS.md

Этот файл описывает правила для coding-агентов, которые работают в этом репозитории.

## Контекст Проекта

- Это статическая браузерная игра без фреймворка и без bundler.
- Основной стек: `HTML + CSS + vanilla JS`.
- Игра про пункт выдачи заказов `Osome`.
- Основная механика текущей версии: tap по клиенту с цветовым типом, совпадающим с коробкой на стойке.
- Если от выбранного клиента собирается ортогонально связная группа `3+` того же цветового типа, она убирается целиком одним тапом.
- Связность считается только по ходам ладьи: вверх, вниз, влево, вправо. Диагонали не считаются.
- Темп спавна сейчас адаптивный: базовая кривая растёт по времени, но дополнительно подстраивается под скорость игрока.

## Главные Файлы

- `index.html` — структура UI и сцены
- `styles.css` — весь визуальный слой
- `game.js` — рантайм игры
- `balance-config.js` — фазы сложности и параметры давления
- `scripts/simulate-balance.cjs` — симулятор баланса
- `assets/icons/` — SVG-иконки и вспомогательные графические ассеты
- `assets/brand/` — логомарк и брендовые варианты

## Обязательные Правила

1. Не добавляй фреймворк, bundler или TypeScript без прямого запроса пользователя.
2. Не дроби игру на большое число файлов без реальной причины.
3. Не меняй механику баланса вслепую. Если меняется темп игры, прогоняй симулятор.
4. Не коммить случайные брендовые черновики или ассеты, если пользователь этого не просил.
5. Не трогай незакоммиченные пользовательские изменения, если они не относятся к задаче.

## Как Работать С Геймплеем

Если меняется логика:

- спавна
- выбора товара на стойке
- начисления очков
- гиммиков
- роста сложности

нужно прогнать:

```bash
npm run lint
npm run format:check
npm run balance:simulate -- --runs 180
```

Если меняется только визуал, достаточно:

```bash
npm run lint
npm run format:check
```

## Как Работать С Балансом

- Источник истины по темпу игры: `balance-config.js`
- Не хардкодь новые фазы в `game.js`, если их можно выразить в конфиге
- При тюне стремись сохранять целевой профиль:
  - старт должен ощущаться агрессивным
  - средняя сессия должна жить около `10-12` минут
  - рост сложности должен быть виден даже при adaptive spawn
- Для сравнений используй `scripts/simulate-balance.cjs`
- Помни, что `casual / solid / expert` — это только профили симулятора, а не режимы реальной игры

## Как Работать С Визуалом

- Сцена должна оставаться читаемой с первого взгляда
- Главное на экране: очередь, товар на стойке и HUD
- Любой декор не должен мешать:
  - кликабельности клиентов
  - читаемости цветового матчинга
- Не перегружай интерфейс маленькими подписьми и второстепенными карточками

## Как Работать С Ассетами

- SVG предпочтительнее растровых изображений
- Новые игровые иконки и интерьерные предметы делай в одном визуальном языке
- Если файл добавлен как черновик и не используется, не подсовывай его в коммит автоматически

## Коммиты

- Коммит должен быть узким по смыслу
- Не смешивай в один коммит:
  - ребаланс
  - редизайн сцены
  - новые ассеты
  - рефактор логики

Хорошо:

- `Tune progression curve`
- `Refine item icons`
- `Add horned Osome logomark`

Плохо:

- `misc fixes`
- `update game`

## Проверки Перед Завершением

Минимум:

```bash
npm run format:check
npm run lint
```

Если затронут баланс:

```bash
npm run balance:simulate -- --runs 180
```

Если затронуты git-хуки или проверка секретов:

```bash
npm run secrets:check
```

## Что Лучше Не Делать

- Не тащи в проект тяжелые зависимости ради маленькой задачи
- Не заменяй статическую архитектуру SPA-фреймворком
- Не усложняй DOM там, где можно решить через CSS и простую разметку
- Не ломай tap-only механику без прямого запроса
- Не переписывай баланс “на глаз” без симуляции
